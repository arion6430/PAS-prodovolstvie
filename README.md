# Прогнозно-аналитическая система цен на плодоовощную продукцию

Учебный проект по дисциплине «Прогнозно-аналитические системы», профиль «Управление данными».
Тема 8 — продовольственный рынок.

**Прогнозируемый показатель:** средняя потребительская цена (руб/кг) на плодоовощную продукцию в разрезе РФ, федеральных округов, Москвы и Санкт-Петербурга. Горизонт прогноза — 1–3 месяца.
**Пользователь:** аналитик закупок торговой сети или регионального органа, который следит за продовольственными ценами.

Постановка задачи и анализ источников: [docs/01_Постановка_задачи_и_данные.md](docs/01_Постановка_задачи_и_данные.md).

## Архитектура

```
Источники ──► загрузчики (Python) ──► raw ──► staging ──► core ──► marts ──► Superset
             инкрементально,         PostgreSQL       dbt: очистка, справочники,
             журнал meta.load_log                     SCD2-снимки, тесты качества
                     ▲                                        ▲
                     └────────────── Airflow (ежедневно 06:00 МСК) ──────────┘
```

| Компонент | Технология | Назначение |

### Как устроена загрузка

* **Инкрементальность.** Для каждого источника из хранилища берётся последняя загруженная дата, и запрашивается только новое: курсы и ставка — со следующего дня, погода — с перекрытием 10 дней (последние дни архива предварительные), ЕМИСС — последние 2 года (Росстат уточняет опубликованные значения).
* **Идемпотентность.** Запись в raw — upsert по естественному ключу: новый ключ вставляется, изменившееся значение обновляется, совпадающее не трогается. Повторный запуск с теми же данными ничего не меняет (`status = unchanged`).
* **Устойчивость к сбоям.** Таймауты, до 4 повторов с экспоненциальной паузой при сетевых ошибках, 429 и 5xx (учитывается `Retry-After`), ограничение частоты запросов к хосту. Сбой одного запроса не прерывает остальные (`status = partial`), сбой одного источника не мешает другим. Загрузки, прерванные аварийно, при следующем запуске помечаются `failed`.
* **Контроль структуры ответа.** Если в ответе нет ожидаемых полей или в справочнике источника пропало нужное значение, загрузка падает с `SchemaChanged` или пишет предупреждение в журнал.
* **Сырые ответы** сохраняются в `data/raw/<источник>/` в gzip; имя файла — SHA-256 содержимого без изменчивых частей. Одинаковый ответ хранится один раз, каждая строка raw ссылается на файл, из которого пришла (`_content_hash`).
* **Журнал загрузок** `meta.load_log`: источник, запуск Airflow, статус, параметры окна, число запросов и ошибок, строк получено/новых/изменённых/без изменений, предупреждения, текст ошибки. Файлы каждой загрузки — `meta.load_files`, `meta.raw_files`.
* **Миграции схемы** — версионированные файлы `sql/migrations/V###__*.sql`, применённые фиксируются в `meta.schema_migrations` с контрольной суммой.

## Запуск

Нужен только Docker Desktop (Windows/macOS) или Docker Engine + Compose (Linux).

```bash
cp .env.example .env          # при желании смените пароли
docker compose up -d --build  # PostgreSQL + Airflow; первая сборка ~5 минут
```

* Airflow: http://localhost:8080 (логин/пароль из `.env`, по умолчанию admin/admin). DAG `foodprices_pipeline` включён и запускается ежедневно в 06:00 МСК; запустить сразу — кнопка ▶ Trigger.
* PostgreSQL доступен с хоста на порту `5433` (см. `.env`).

Загрузка без Airflow (из контейнера):

```bash
docker compose run --rm airflow-scheduler python -m foodprices ingest --source all
docker compose run --rm airflow-scheduler python -m foodprices status
```

Локальная разработка и тесты:

```bash
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"   # Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m pytest
.venv/Scripts/python -m foodprices ingest --source cbr_fx      # пишет в PostgreSQL из docker (порт 5433)
```
